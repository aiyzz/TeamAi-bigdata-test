# 能力6：基准表溯源验证

## 能力说明

新增表场景下，通过基准表（明细表）+ 维表验证测试表的正确性。不比对数据量，只比对记录存在性和字段值。

## 验证流程

```
Step 0: 前置检查（容错）
         ├─ 基准表分区存在性
         ├─ 基准表数据延迟
         ├─ 分区格式一致性
         └─ 数据量异常检查
         ↓
Step 1: 口径判断
         测试表与基准表是同口径还是子集口径
         ↓
Step 2: 记录完整性验证（双向）
         正向：测试表多出？
         反向：测试表漏了？
         ↓
Step 3: 字段值验证
         A类：直接映射
         B类：维表关联
         C类：计算转换
         D类：常量
         E类：字典映射
         F类：不可溯源
         ↓
Step 4: F类字段处理
         列出询问用户
```

## Step 0: 前置检查（容错）

### 检查清单

| 检查项 | 检查方式 | 异常处理 |
|--------|----------|----------|
| 基准表分区存在 | SQL 0.1 | 终止 |
| 基准表数据延迟 | SQL 0.2 | 警告 |
| 测试表有数据 | SQL 0.3 | 终止 |
| 基准表有数据 | SQL 0.4 | 终止 |
| 数据量比值 | test_cnt / base_cnt | 警告 |

### 检查流程

```
分区存在性检查
  ├─ 基准表分区不存在 → ❌ 终止，提示用户
  └─ 基准表分区存在 → 继续
      ↓
数据延迟检查
  ├─ 基准表最新分区 < 测试表分区 → ⚠️ 警告，提示用户确认
  └─ 基准表最新分区 >= 测试表分区 → 继续
      ↓
分区格式一致性检查
  ├─ 格式不一致 → ⚠️ 警告，自动转换
  └─ 格式一致 → 继续
      ↓
数据量异常检查
  ├─ 任一表无数据 → ❌ 终止
  ├─ 数据量比值异常（>1.5 或 <0.5）→ ⚠️ 警告，提示用户确认
  └─ 数据量正常 → 继续验证
```

## Step 1: 口径判断

### 判断规则

| 判断依据 | 同口径 | 子集口径 |
|----------|--------|----------|
| 测试表名含业务场景词（揽收/签收/派件） | | ✅ |
| ETL 代码有 op_code 筛选条件 | | ✅ |
| ETL 代码有 org_type 筛选条件 | | ✅ |
| 测试表与基准表结构完全一致 | ✅ | |

### 子集口径筛选条件来源

从 ETL 代码或需求文档中提取筛选条件。

---

## Step 2: 记录完整性验证（双向）

### 验证逻辑

**正向**：测试表 LEFT JOIN 基准表（筛选后）
- unmatched_cnt > 0 → 测试表有异常多出的记录

**反向**：基准表（筛选后）LEFT JOIN 测试表
- missing_cnt > 0 → 测试表漏了基准表的记录

### 判定规则

- unmatched_cnt = 0 且 missing_cnt = 0 → ✅ PASS
- 任一 > 0 → ❌ FAIL

---

## Step 3: 字段值验证

### 字段溯源分类（6类）

| 分类 | 说明 | 验证方式 | 是否需用户确认 |
|------|------|----------|----------------|
| **A类：直接映射** | test.field = detail.field | 直接比对 | 否 |
| **B类：维表关联** | test.field = dim.field（通过 detail.code） | 关联维表比对 | 否 |
| **C类：计算转换** | test.field = func(detail.field) | 补充转换逻辑后比对 | 否 |
| **D类：常量** | test.field = '固定值' | 直接比对常量 | 否 |
| **E类：字典映射** | test.field = CASE WHEN ... | 按映射规则比对 | 否 |
| **F类：真正不可溯源** | ETL 代码中无来源 | 列出询问用户 | 是 |

### 分类决策树

```
读取 ETL 代码中该字段的定义
    │
    ├─ test.field = detail.field
    │   → A类：直接映射
    │
    ├─ test.field = dim.field (via detail.code)
    │   → B类：维表关联
    │
    ├─ test.field = func(detail.field)
    │   → C类：计算转换
    │
    ├─ test.field = '固定值'
    │   → D类：常量
    │
    ├─ test.field = CASE WHEN detail.field ... THEN ... END
    │   → E类：字典映射
    │
    └─ 无定义
        → F类：不可溯源
```

### C类计算转换示例

| 转换类型 | 示例 | 验证表达式 |
|----------|------|------------|
| 单位转换 | 重量克转千克 | `weight / 1000` |
| 日期格式化 | yyyyMMdd | `DATE_FORMAT(dt, '%Y%m%d')` |
| 字符串拼接 | 网点+操作码 | `CONCAT(org_code, op_code)` |
| 截取 | 取前3位 | `SUBSTRING(code, 1, 3)` |
| 四舍五入 | 保留2位 | `ROUND(amount, 2)` |
| 空值填充 | 默认值 | `COALESCE(field, '默认')` |

### E类字典映射示例

| ETL 逻辑 | 验证表达式 |
|----------|------------|
| `CASE WHEN status='1' THEN '有效' ELSE '无效' END` | 按映射规则比对 |
| `CASE WHEN op_code IN ('310','311') THEN '揽收' ELSE '其他' END` | 按映射规则比对 |

### 判定规则

- diff_cnt = 0 → ✅ PASS
- diff_cnt > 0 → ❌ FAIL

## Step 4: F类字段处理

### F类：真正不可溯源

仅以下情况归为 F 类：
- ETL 代码中完全没有该字段的定义
- 字段来源是其他非基准表，且无法确定是哪张表
- 字段是业务系统实时写入，无固定逻辑

### 输出格式

```markdown
### F类：不可溯源字段

| 测试字段 | 字段类型 | 字段注释 | 原因 | 用户指定验证表 |
|----------|----------|----------|------|----------------|
| custom_flag | varchar | 自定义标记 | ETL 代码中未定义 | 待确认 |
| realtime_score | int | 实时评分 | 业务系统实时写入 | 待确认 |
```

## 性能优化

| 场景 | 优化策略 | 说明 |
|------|----------|------|
| 亿级明细表 JOIN | 分区裁剪 + 主键先过滤 | 子查询先过滤分区和主键 |
| 记录数 > 1000万 | 分批次验证 | 按主键范围分批 |
| 维表关联 | 小表广播 / MapJOIN | 维表通常较小，可用 MapJOIN |
| 差异统计 | 避免 SELECT * | 只取需要的字段 |
| 未匹配记录明细 | LIMIT 限制 | 只取样例，不取全量 |
