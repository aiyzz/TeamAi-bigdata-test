# 能力 5：SQL 审核

> 审核将要执行的 SQL 是否符合模板规范。在执行能力之前，确保所有 SQL 都遵循标准格式。

---

## 触发条件

所有验证任务必定触发（与能力0类似，作为前置检查）。

---

## 输入

| 参数 | 必填 | 说明 |
|------|------|------|
| 激活能力清单 | 是 | Step 3 确定的能力列表 |
| SQL 初稿文件 | 是 | Step 4 生成的 `sql_draft.md` |
| SQL 模板文件 | 是 | 对应能力的模板文件 |

---

## 审核范围

根据激活能力清单，确定需要审核的 SQL 模板：

| 已激活能力 | 对应 SQL 模板 | 审核内容 |
|-----------|--------------|----------|
| 能力0（数据质量） | `common/quality-check-sql.md` | 空表检查、主键唯一性、维度空值占比、指标分布等结构完整性 |
| 能力1（不变更记录） | `cap-1-unchanged-verify-sql.md` | 字段比对 SQL 的 NULL 处理三段式格式 |
| 能力2（增加记录） | `cap-2-increase-verify-sql.md` | 来源追溯使用 `NOT EXISTS`、筛选条件使用 CASE WHEN |
| 能力3（减少记录） | `cap-3-decrease-verify-sql.md` | 剔除逻辑使用 `NOT EXISTS`、误删排查结构 |
| 能力4（字段增减） | `cap-4-schema-change-sql.md` | 原有字段保护三段式、新增字段验证使用 `NVL(CAST(...))` |
| 主流程（数据量统计） | `common/diff-rows-count-sql.md` | 新增用 LEFT JOIN、减少用 RIGHT JOIN |
| 主流程（字段结构比对） | `common/field-structure-compare-sql.md` | 字段数量、新增字段、删除字段查询结构 |

---

## 审核检查清单

### 通用检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 分区条件声明 | 所有 SQL 包含 `dt = '<分区值>'` | 缺少分区条件 |
| 表名完整 | 使用 `database.table_name` 格式 | 表名不完整 |
| 主键正确 | JOIN 条件使用正确的主键 | 主键字段错误 |

### 能力0（数据质量）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 空表前置检查 | 同时检查测试表和生产表 | 只检查单表 |
| 主键唯一性 | `GROUP BY <主键> HAVING count(*) > 1` | 结构错误 |
| 维度空值占比 | `UNION ALL` 批量执行所有维度字段 | 未批量或字段遗漏 |
| 指标空值+零值占比 | `UNION ALL` 批量执行所有指标字段 | 未批量或字段遗漏 |
| 指标统计分布 | 包含 MIN/MAX/AVG 查询 | 缺少统计分布 |

### 能力1（不变更记录）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 字段比对 NULL 处理 | 使用三段式：`a.field != b.field OR (a.field IS NULL AND b.field IS NOT NULL) OR (a.field IS NOT NULL AND b.field IS NULL)` | 缺少 NULL 处理 |
| 字段比对批量 | 使用 `UNION ALL` 批量执行所有共同字段 | 未批量或字段遗漏 |
| 共同记录数 | 使用 `INNER JOIN` 统计 | JOIN 类型错误 |

### 能力2（增加记录）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 来源追溯匹配 | 使用 `NOT EXISTS` 子查询排除生产表记录 | 未使用 EXISTS 结构 |
| 筛选条件符合性 | 使用 `NOT EXISTS` + `CASE WHEN` 分组 | 未使用 EXISTS 或 CASE WHEN |
| 不符合条件排查 | 包含排查明细查询 | 缺少排查查询 |

### 能力3（减少记录）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 剔除逻辑验证 | 使用 `NOT EXISTS` 子查询排除测试表记录 | 未使用 EXISTS 结构 |
| 误删排查 | 包含误删明细查询 | 缺少排查查询 |
| 反向验证 | 包含反向验证查询 | 缺少反向验证 |

### 能力4（字段增减）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 原有字段保护 | 使用三段式 NULL 处理 | 缺少 NULL 处理 |
| 新增字段验证（直接映射） | 使用 `NVL(CAST(... AS STRING), '')` 包裹 | 缺少 NULL 安全处理 |
| 新增字段验证（ETL 转换） | 使用 `NVL(CAST(<转换表达式> AS STRING), '')` 包裹 | 缺少 NULL 安全处理 |
| 新增字段质量检查 | 包含空值占比查询 | 缺少质量检查 |

### 主流程（数据量统计）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 新增记录统计 | `FROM 测试表 LEFT JOIN 生产表 WHERE 生产表主键 IS NULL` | JOIN 方向错误或合并为一个查询 |
| 减少记录统计 | `FROM 测试表 RIGHT JOIN 生产表 WHERE 测试表主键 IS NULL` | JOIN 方向错误或合并为一个查询 |

### 主流程（字段结构比对）检查

| 检查项 | 预期 | ❌ FAIL 条件 |
|--------|------|-------------|
| 字段数量对比 | 使用 `information_schema.columns` 查询 | 查询结构错误 |
| 新增字段查询 | 使用 `LEFT JOIN + IS NULL` | JOIN 结构错误 |
| 删除字段查询 | 使用 `LEFT JOIN + IS NULL` | JOIN 结构错误 |
| 共同字段查询 | 使用 `INNER JOIN` | JOIN 结构错误 |

## 审核流程

### Step 1: 读取 SQL 初稿

读取 `report/{YYYY-MM-DD}/{table_name}_sql_draft.md` 文件，解析所有 SQL 代码块。

### Step 2: 读取模板文件

根据激活能力清单，读取对应的 SQL 模板文件：

```
激活能力清单
    ↓
读取对应模板文件
    ↓
提取审核规则
```

### Step 3: 逐条审核

对 SQL 初稿中的每条 SQL：

1. **识别 SQL 类型**：根据章节标题判断属于哪个能力/测试点
2. **匹配审核规则**：从审核清单中找到对应的检查项
3. **执行检查**：
   - 检查 SQL 结构是否符合模板
   - 检查 NULL 处理是否使用三段式
   - 检查是否使用 `NOT EXISTS` 结构
   - 检查是否使用 `NVL(CAST(...))` 包裹
4. **记录结果**：标记 ✅ PASS 或 ❌ FAIL

### Step 4: 修正偏差

对 ❌ FAIL 的 SQL：

1. **读取模板**：找到对应的 SQL 模板
2. **生成正确 SQL**：根据模板和实际表名/字段名生成正确的 SQL
3. **替换原 SQL**：用修正后的 SQL 替换初稿中的对应内容
4. **记录修正说明**：记录修正原因

### Step 5: 生成审核报告

生成 `report/{YYYY-MM-DD}/{table_name}_sql_audit.md` 文件：

```markdown
# SQL 审核报告

## 审核概要

| 项目 | 内容 |
|------|------|
| 审核时间 | YYYY-MM-DD |
| 激活能力 | 能力0, 能力1, 能力2, ... |
| 审核SQL数量 | N 条 |
| 通过数量 | M 条 |
| 偏差数量 | K 条 |

---

## 审核结果

| 测试点 | SQL 类型 | 是否遵循模板 | 修正说明 |
|--------|----------|-------------|----------|
| 0.1 | 空表前置检查 | ✅ 是 | - |
| 0.2 | 主键唯一性 | ✅ 是 | - |
| 1.1 | 字段比对 | ❌ 否 | 已修正：补充完整UNION ALL所有字段 |
| ... | ... | ... | ... |

**审核结论**：全部通过 / 存在 N 处偏差已修正

---

## 审核通过的 SQL

（修正后的完整SQL，按能力分组）
```

## 审核标准

| 结果 | 状态 | 说明 |
|------|------|------|
| 所有 SQL 符合模板 | ✅ PASS | 可以执行 |
| 部分 SQL 存在偏差 | ⚠️ WARN | 修正后执行 |
| 关键 SQL 结构错误 | ❌ FAIL | 需要重新生成 |

---

## 注意事项

1. **审核范围**：只审核已激活的能力对应的 SQL，未激活的不审核
2. **审核时机**：在执行能力之前审核，确保 SQL 正确
3. **修正记录**：所有修正必须记录到审核报告中
4. **模板优先**：当 SQL 与模板不一致时，以模板为准
5. **业务逻辑**：审核只检查 SQL 结构，不检查业务逻辑正确性
